## Standing findings, evidence gathered, not yet fixed

Verified by an adversarial audit (38 agents, every finding independently refuted before being kept)
and written up in full in [`docs/design/arrival-2026-09.md`](../../docs/design/arrival-2026-09.md) §5.
Ranked by how badly they mislead:

1. **`getStandingRecord` counts with `.eq("user_id", userId)` and no workspace filter** - an empty
   workspace prints _"A run has read 118 of these back"_ above _"Nothing learned yet."_ The same
   number gates `recordIsBlank`, so the designed zero state never fires. **Same class as the Start
   defect fixed in `0e1b964a6`, in a second place.**
2. **The discover source count** is taken with no workspace filter and cached under a
   workspace-free key, so an empty workspace is offered no source to connect - the one remedy
   withheld at the one moment it is needed.
3. **`ArtifactPane`** says _"Discover has not run yet"_ while Discover is running (`driven_at` is
   stamped only on the driver's exit paths), and _"press an artifact in the record beside this"_
   when the record says nothing is recorded.
4. **`RetentionLine`** warns that a record the person does not have expires in 30 days.
5. **Two "Saved" resting labels** under headings that just said nothing was ever set.
6. **`DataSection`** boasts _"0 decisions closed and 0 pull requests shipped"_ - an object of zeros
   is truthy, so the fallback written for this case is unreachable.
