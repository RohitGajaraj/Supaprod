# Mission: Final Production Readiness Audit & Consumer-Ready Product Transformation

> _Created: 2026-08-03 · Last updated: 2026-08-03_

This is the final release before shipping. Your goal is **not** to make
incremental improvements but to transform the application into a
polished, premium, enterprise-grade product that is consumer-ready,
investor-ready, and YC-ready.

You have full autonomy. Use every available agent, MCP, workflow,
sub-agent, Playwright, Lovable, Supabase, UI/UX Pro Max, Emil Kowalski
taste, frontend, QA, security, accessibility, testing, architecture,
design, and autonomous workflow available. Work in parallel wherever
possible and plan your execution before implementation.

## 1. Complete Product Audit

Perform an end-to-end audit of the codebase, architecture, frontend,
backend, UX, UI, information architecture, design system, functionality,
engineering quality, security, accessibility, performance, production
readiness, and live deployment.

Never assume the codebase reflects production. Validate everything
against the deployed application.

## 2. Recover & Organize Features

Previous versions contained significantly more functionality (Settings,
Pricing, Governance, Engine Room, etc.). Many features have disappeared
or become "homeless."

Recover every missing capability, logically regroup and rename where
necessary, improve navigation and discoverability, and ensure every
feature is visible, functional, and belongs in a logical location.

If you identify missing workflows, usability gaps, or gray areas that
should exist, implement them proactively.

## 3. Premium UX & Visual Redesign

The current Obsidian V3 implementation is not meeting expectations.

Current issues include poor readability, harsh orange contrast, weak
typography, inconsistent interactions, hidden UI, incomplete screens,
low visual hierarchy, and a loss of the premium feel.

You are free to improve, combine, or replace parts of any previous
design system. Do not feel constrained by V3.

Design a product that is modern, elegant, calm, premium, minimal, and
highly usable with refined spacing, typography, animations, transitions,
micro-interactions, optional tasteful 3D illustrations/icons, polished
components, and intuitive navigation. If installing fonts, shadcn
components, or additional UI libraries improves the experience, do so.

## 4. Content & Product Language Audit

Audit every label, button, menu, tooltip, heading, empty state, success
message, error message, notification, onboarding flow, and generated
artifact.

Ensure naming is concise, logical, modern, human, and consistent.

The application is built for Product Managers, so the language should
naturally reflect product thinking with occasional tasteful humor and
personality without becoming unprofessional.

Remove AI fingerprints everywhere: - No em dashes or en dashes - No
invisible characters - No AI-style wording or formatting - Human-quality
writing throughout

## 5. Production Validation

Continuously publish when required, execute Playwright end-to-end
testing, validate production behavior, verify backend logic where
appropriate, fix every issue discovered, and repeat until stable.

Do not stop at code-level testing.

## 6. Final Production Audit

Review and improve: - Architecture - Engineering quality - QA - Smoke
testing - Security vulnerabilities - Threat analysis - Accessibility -
Performance - Responsiveness - Error handling - Empty/loading states -
Navigation - Discoverability - Consistency - Information architecture -
Overall product quality

Treat this exactly as the final production release.

Seed rich demo data only after the platform is fully stable and
production-ready.

## 7. Design Inspiration

Study these references for principles only:

https://www.interfacecraft.dev/

https://devouringdetails.com/

Capture their premium quality, visual hierarchy, smooth interactions,
thoughtful layouts, reduced cognitive load, delightful experience, and
attention to detail. If you discover better references, use them.

## Final Success Criteria

When complete, the application should feel comparable in polish to
products like Linear, Notion, Figma, Stripe, Vercel, or Perplexity.

Every feature should be discoverable, every workflow should feel
intentional, every interaction should be smooth, and every screen should
deliver value.

The application should never confuse or overwhelm users. It should feel
premium, cohesive, fast, modern, and thoughtfully designed from
engineering, architecture, UX, UI, QA, security, accessibility,
functionality, and product perspectives.

If you discover improvements that I did not explicitly mention,
implement them. Make independent product decisions where appropriate.

The objective is that after this pass, I should not need another review
cycle before shipping.
