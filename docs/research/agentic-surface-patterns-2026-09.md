## Lovable

1. **Landing.** Marketing headline "Build something Lovable" with one prompt box; inside the app the box reads "Ask Lovable to create…" and is "front and center", with three starter prompts in the docs and a templates page to remix ([lovable.dev](https://lovable.dev/), [quick start](https://docs.lovable.dev/introduction/getting-started)). Under ten seconds to "I get it": one box, one verb.
2. **Running.** Chat left, live preview right. Work appears as "activity cards that track its individual actions: file edits, commands, web searches, browser tests, and the subagents it delegates research to"; bigger Build-mode requests also show a task list ([chat docs](https://docs.lovable.dev/features/projects/chat), [Build mode](https://docs.lovable.dev/features/agent-mode)). You keep typing: queued messages sit greyed out until picked up; answers to its question cards steer the current run ([chat docs](https://docs.lovable.dev/features/projects/chat)).
3. **Afterwards.** Each response "shows what changed" with an activity card, a Details link, a per-message Preview of the app at that point, and the credits it cost ([chat docs](https://docs.lovable.dev/features/projects/chat)). Publish ends with "Your website is live", copy link, visit, and a search-result preview ([publish](https://docs.lovable.dev/features/publish)).
4. **Depth.** Click any activity card and the Details view "opens where the preview usually appears", Timeline tab of every step and tool call, Changes tab of file diffs; "Hide details" returns to the preview. Subagent rows expand to files inspected and findings returned ([Build mode](https://docs.lovable.dev/features/agent-mode), [subagents](https://docs.lovable.dev/features/subagents)).
5. **Hidden.** The code itself, unless you open Code view; subagents run "in the background" and "you don't have to think about any of this", yet stay traceable in the activity view ([subagents blog](https://lovable.dev/blog/subagents-in-lovable)).
6. **Intervention.** Plan mode gates code changes behind a discussion; Publish is a click, or a chat request that "asks for approval before publishing unless you have set the publish tool to auto-approve"; one-click Undo latest edit, Revert to this version, Edit message and Revert and resend; a Try to fix button on build errors ([publish](https://docs.lovable.dev/features/publish), [chat docs](https://docs.lovable.dev/features/projects/chat)).

## Replit Agent

1. **Landing.** "Hi [Name], what do you want to make?" above one box, with chips for Web app, Data app, Game, and Improve prompt; sidebar shows Apps quota and Usage even on free ([HostAdvice](https://hostadvice.com/ai-app-builders/cursor-vs-replit/), [Contrary](https://research.contrary.com/report/replit)). Under ten seconds.
2. **Running.** A Plan tab first, then "a visual preview window came alive" on the right while the agent narrates in chat; a reviewer called it "a contractor narrating their work" with a plain-language build log ([HostAdvice](https://hostadvice.com/ai-app-builders/replit-review/), [timtis](https://www.timtis.com/blog/i-gave-replit-agent-one-prompt-fifteen-minutes-later-i-had-a-live-ticket-booking-website/)). Follow-ups default to Steer (inject into the active turn) or Queue (a drawer above the input, reorderable); Stop sits in the status bar ([message queue](https://docs.replit.com/features/agent/message-queue)).
3. **Afterwards.** A checkpoint per task; the run log records minutes worked and a status such as "complete and running cleanly" and, unprompted, opens a Publish panel with the subdomain pre-checked ([timtis](https://www.timtis.com/blog/i-gave-replit-agent-one-prompt-fifteen-minutes-later-i-had-a-live-ticket-booking-website/)). Background tasks end with "the work log, test results, and a live preview" plus Apply or Dismiss ([task system](https://docs.replit.com/core-concepts/agent/task-system)).
4. **Depth.** History in the Agent panel lists checkpoints, each with Changes and Rollback here, and rollback confirms what it will restore first ([build guide](https://docs.replit.com/learn/build-with-agent)). Tasks run in a thread view or a board (Drafts, Active, Ready, Done) you can jump into ([task system](https://docs.replit.com/core-concepts/agent/task-system)).
5. **Hidden.** Environment, packages, deploy config; the agent "tests its own work on a regular basis" without showing tests unless asked ([agent docs](https://docs.replit.com/replitai/agent)). It does not feel opaque because each checkpoint is a diff you can open.
6. **Intervention.** Edit Plan / Approve Plan (or Start building) before code; "Debug with Agent" on a crash banner; paid actions ask "Allow once"; Publish is a click with a security scan step ([HostAdvice](https://hostadvice.com/ai-app-builders/replit-review/), [agent docs](https://docs.replit.com/replitai/agent), [plan mode](https://docs.replit.com/replitai/plan-mode)).

## Devin

1. **Landing.** A session page with an Ask / Agent toggle, a repository selector, and an agent picker (Devin, Fast Mode, Dana) ([first run](https://docs.devin.ai/get-started/first-run)). Headline copy: unverified. The mode toggle costs a few seconds of orientation; call it 20 seconds.
2. **Running.** Interactive Planning returns "relevant files, findings, and a preliminary plan" in seconds with code citations, then waits 30 seconds by default before proceeding ([planning](https://docs.devin.ai/work-with-devin/interactive-planning)). A Progress tab unifies shell, code edits and browser activity per step; the older "Follow Devin" tab highlighted actions with a magnifier to jump to the tool ([session tools](https://docs.devin.ai/work-with-devin/devin-session-tools), [2024 notes](https://docs.devin.ai/release-notes/2024)). You can talk without interrupting: `/btw` opens a read-only side chat "and the main session keeps running the whole time" ([session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)).
3. **Afterwards.** A PR link and summary in chat; PR Preview shows the diff before a PR exists; Session Insights generates "a timeline of what happened, actionable feedback, and an improved prompt" ([first run](https://docs.devin.ai/get-started/first-run), [2024 notes](https://docs.devin.ai/release-notes/2024)). Work log accordions carry a self-graded retro per step with time spent ([2024 notes](https://docs.devin.ai/release-notes/2024)).
4. **Depth.** Click any step to open it; shell history is time-navigable, greyed commands are "run at a future point", click to jump; the IDE is real VS Code with diff view; Desktop tab is the agent's browser ([session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)).
5. **Hidden.** The VM reset and setup, ACU accounting until a low-ACU toast fires ([2024 notes](https://docs.devin.ai/release-notes/2024)). Not a black box because every step links to the tool that produced it.
6. **Intervention.** "Wait for my approval" on the plan; stop the session to take over the IDE, then tell Devin what you changed; sleep/wake; PR review stays on GitHub ([planning](https://docs.devin.ai/work-with-devin/interactive-planning), [session tools](https://docs.devin.ai/work-with-devin/devin-session-tools)).

## Claude Code on the web, desktop, and CLI

1. **Landing.** Web: on desktop OS the first screen offers the desktop app, with "Continue on web" at the bottom; then one input with a repository and branch selector below it; sessions list in the sidebar ([web quickstart](https://code.claude.com/docs/en/web-quickstart)). Prompt placeholder: unverified. CLI: a grayed example command picked from recent git history ([interactive mode](https://code.claude.com/docs/en/interactive-mode)). Web is about 15 seconds because of the GitHub connect step.
2. **Running.** Web: "You can watch and steer throughout, or step away"; per-file diffs render as Claude edits; a `+42 -18` indicator tracks the session ([web quickstart](https://code.claude.com/docs/en/web-quickstart), [web reference](https://code.claude.com/docs/en/claude-code-on-the-web)). Desktop: chat, diff, browser, terminal, tasks, subagent panes; stop button, or type a correction that lands "as soon as the current action completes" ([desktop](https://code.claude.com/docs/en/desktop)). CLI: Esc interrupts and keeps work so far; Enter while running queues; Ctrl+T shows the to-do checklist ([interactive mode](https://code.claude.com/docs/en/interactive-mode)).
3. **Afterwards.** Branch pushed, diff view with file list left and changes right, Create PR (full, draft, or GitHub compose) at the top; session stays open, and a CI status bar carries an Auto-fix toggle ([web quickstart](https://code.claude.com/docs/en/web-quickstart), [web reference](https://code.claude.com/docs/en/claude-code-on-the-web)). CLI: a one-line recap when you come back after three minutes away ([interactive mode](https://code.claude.com/docs/en/interactive-mode)). Cost display: unverified.
4. **Depth.** Ctrl+O toggles a transcript with timestamps and per-message model; desktop cycles Normal (tool calls collapsed), Verbose, Summary (final responses and changes only) ([interactive mode](https://code.claude.com/docs/en/interactive-mode), [desktop](https://code.claude.com/docs/en/desktop)). Inline diff comments queue and bundle into the next message ([web quickstart](https://code.claude.com/docs/en/web-quickstart)).
5. **Hidden.** MCP calls collapse to "Called slack 3 times"; the auto-mode classifier runs unseen and "sees only user messages and the agent's tool calls" ([interactive mode](https://code.claude.com/docs/en/interactive-mode), [auto mode](https://www.anthropic.com/engineering/claude-code-auto-mode)). Legible because the collapse is one keystroke from expansion.
6. **Intervention.** Permission modes: Manual, acceptEdits, plan, auto, dontAsk, bypass; auto is the starting mode on Pro, Max and Team; Shift+Tab cycles; web offers Accept edits, Plan, Auto from a dropdown changeable mid-run ([permission modes](https://code.claude.com/docs/en/permission-modes), [web quickstart](https://code.claude.com/docs/en/web-quickstart)). PR creation and merge remain clicks.

## OpenAI Codex (cloud)

1. **Landing.** "What are we coding next?" with Ask and Code buttons, environment picker, and three suggested starter tasks (explain the codebase, find bugs, fix typos) as cards ([proflead](https://dev.to/proflead/how-to-use-chatgpt-codex-from-openai-4an8), [MarkTechPost](https://www.marktechpost.com/2025/07/03/a-tutorial-on-using-openai-codex-with-github-repositories-for-seamless-ai-powered-development/)). Environment creation comes first, so 30 to 60 seconds before the box is usable.
2. **Running.** A task list with status text: "Starting container", "Downloading repo", "Reading AGENTS.md", "Exploring files", "Thinking", "Running a command" ([proflead](https://dev.to/proflead/how-to-use-chatgpt-codex-from-openai-4an8)). "You can watch the task logs or let the task run in the background" ([Codex cloud](https://learn.chatgpt.com/docs/cloud)). Mid-task chat while it runs: unverified; follow-ups go in the same thread after completion ([review workflow](https://developertoolkit.ai/en/codex/quick-start/review-workflow/)).
3. **Afterwards.** "It shows its answer and a diff of any files it changed", then Create PR or Check out locally ([cloud environment](https://learn.chatgpt.com/docs/environments/cloud-environment), [review workflow](https://developertoolkit.ai/en/codex/quick-start/review-workflow/)). Best-of-N returns several attempts to choose from ([MarkTechPost](https://www.marktechpost.com/2025/07/03/a-tutorial-on-using-openai-codex-with-github-repositories-for-seamless-ai-powered-development/)).
4. **Depth.** A Logs tab with every command and the reasoning ([proflead](https://dev.to/proflead/how-to-use-chatgpt-codex-from-openai-4an8)). The desktop app adds a task sidebar with plan, sources, artefacts and summary "rather than watching a stream of tool calls scroll past" ([Vaughan](https://codex.danielvaughan.com/2026/04/17/codex-app-workspace-pr-review-task-sidebar-artifact-viewer/)).
5. **Hidden.** Network is off in the agent phase; secrets are stripped before it; the whole loop runs offline in a container ([cloud environment](https://learn.chatgpt.com/docs/environments/cloud-environment)). The Logs tab is the answer to "opaque-box AI" ([Educative](https://www.educative.io/blog/openai-codex-tutorial)).
6. **Intervention.** Ask vs Code chosen per task; no per-action approval in the cloud; PR creation is a click and review happens on GitHub, optionally with `@codex review` ([review workflow](https://developertoolkit.ai/en/codex/quick-start/review-workflow/)).

## Cursor cloud agents

1. **Landing.** cursor.com/agents: a prompt box with a repository dropdown populated after GitHub connect; the web page reads "Spawn cloud agents on the go" ([BestHub](https://www.besthub.dev/articles/mastering-cursor-cloud-agents-a-complete-usage-guide-0a740a6c9cad), [eesel](https://www.eesel.ai/blog/cursor-ios-app)). Environment setup is agent-led and can run while you set defaults ([setup guide](https://cursor.com/for/cloud-agents)). Placeholder text: unverified.
2. **Running.** The run page shows the conversation, code changes, and artefacts; the dashboard logs events (setup started, PR created, artifact created) ([cloud agents](https://cursor.com/docs/cloud-agent), [capabilities](https://cursor.com/docs/cloud-agent/capabilities)). Follow-ups can be sent while it runs, from web or Slack ([Slack](https://cursor.com/docs/integrations/slack.md)). Explicit stop control: Delete "Stop and archive" in Slack; web stop button unverified.
3. **Afterwards.** "Merge-ready PRs with artifacts to demo their changes": screenshots, videos and logs attached to the PR; a summary, diff, Create PR and Open in Cursor on the run page ([cloud agents](https://cursor.com/docs/cloud-agent), [eesel](https://www.eesel.ai/blog/cursor-ios-app)). Their line is "Demos over diffs" ([cursor.com/cloud](https://cursor.com/cloud)).
4. **Depth.** Take over the agent's remote desktop, test, then "release control back to the agent"; transcripts and setup logs are fetchable in-run ([cloud agents](https://cursor.com/docs/cloud-agent), [capabilities](https://cursor.com/docs/cloud-agent/capabilities)).
5. **Hidden.** VM provisioning, secret redaction, network policy; an admin toggle can hide diff images and code from the sidebar entirely ([settings](https://cursor.com/docs/cloud-agent/settings.md)). Verification artefacts replace watching.
6. **Intervention.** Nothing before the PR; after it, the agent auto-fixes its own CI failures up to ten times and can subscribe to review comments until merge ([capabilities](https://cursor.com/docs/cloud-agent/capabilities)). Merge stays human.

([The Neuron, 2025-12](https://www.theneuron.ai/explainer-articles/vibe-coding-goes-mainstream-inside-vercels-v0-and-the-future-of-building-apps/)), with starter templates and an "enhance my prompt" button. Under ten seconds.
2. **Running.** "v0 started by generating a design brief", then wrote "file by file" visibly; chat left, preview right with Code and Design tabs; "visual progress indicators and rich UI feedback for all agent actions" ([The Neuron](https://www.theneuron.ai/explainer-articles/vibe-coding-goes-mainstream-inside-vercels-v0-and-the-future-of-building-apps/), [v0 docs](https://v0.app/), [quickstart](https://v0.app/docs/quickstart)). Concurrent chat while generating: unverified.
3. **Afterwards.** Each generation is a version with inspect, diff and restore controls on the message; a deployment card "reports live build progress and the final state" with links to site, branch, inspector and build logs ([versions](https://v0.app/docs/versions), [deployments](https://v0.app/docs/deployments)).
4. **Depth.** Code tab is a full editor with Toggle Diff View and split layout; Design mode holds pending edits with before/after preview and commits them as a new version on Apply ([code editing](https://v0.app/docs/code-editing), [design mode](https://v0.app/docs/design-mode)).
5. **Hidden.** Git plumbing: a `v0/main-abc123` branch, a commit per change, "v0 never pushes to main" ([FAQs](https://v0.app/docs/faqs)).

## Linear (agents and first run)

1. **Landing.** Seven one-field steps (theme, team name, import, invite, notifications) with no role or permissions setup, ending in a blinking cursor ([Candu](https://www.candu.ai/blog/linear-onboarding-teardown)). A single "Meet the command menu" screen teaches Cmd+K, then the workspace opens pre-populated with issues titled "Welcome to Linear", "Try 3 ways to navigate Linear", "Connect GitHub or GitLab" ([Masterly](https://www.themasterly.com/blog/saas-onboarding-ux-guide), [Userpilot](https://userpilot.com/blog/saas-user-onboarding-funnel/)). Under 60 seconds and no tour.
2. **Running.** An Agent Session on the issue with six visible states: pending, active, awaitingInput, error, complete, stale; activities of type thought, action (tool call), elicitation, response, error appear in the thread ([agent interaction](https://linear.app/developers/agent-interaction)). The agent must post within 10 seconds or show as unresponsive ([best practices](https://linear.app/developers/agent-best-practices)). Prompt again any time; a stop signal "is generated when a user requests the agent to stop from within Linear" ([signals](https://linear.app/developers/agent-signals)).
3. **Afterwards.** A `response` activity becomes a comment; the session links pull requests and carries a summary ([best practices](https://linear.app/developers/agent-best-practices), [schema](https://raw.githubusercontent.com/linear/linear/master/packages/sdk/src/schema.graphql)).
4. **Depth.** Agents can add external URLs to the session (logs, dashboards); actions carry parameter and result; activities are "frozen-in-time snapshots" ([best practices](https://linear.app/developers/agent-best-practices)).
5. **Hidden.** The agent's runtime entirely; Linear shows only what the agent emits, and ephemeral activities disappear after the next one ([agent interaction](https://linear.app/developers/agent-interaction)).
6. **Intervention.** Assigning sets the agent as delegate, "so humans maintain ownership"; delegated issues stay in My Issues; triage rules can delegate automatically ([assigning](https://linear.app/docs/assigning-issues), [agents](https://linear.app/developers/agents)).

## The six things they all do

- **One box, one verb, no setup screen.** "What do you want to make?", "What are we coding next?", "Ask Lovable to create…", "Let's build something new". Where setup is unavoidable (Codex environments, Claude Code GitHub connect) it is the only thing between sign-in and the box.
- **A plan or assessment as the first return, then a gate.** Replit's Plan tab, Devin's 30-second plan window, Lovable Plan mode, v0's design brief, Perplexity Computer's plan preview with a credit estimate.
- **A collapsed activity stream you can expand without leaving.** Lovable cards to Details, Devin steps to Progress, Claude Code Ctrl+O, Codex Logs tab, Linear activities. The default view hides tool detail; every one of them puts it one click away.
- **Steer without stopping.** Lovable question cards, Replit Steer vs Queue, Claude Code queued messages and mid-action corrections, Devin `/btw`, Cursor follow-ups, Computer's mid-task instructions.
- **The result is a reviewable object, never a status.** Diff plus Create PR (Claude Code, Codex, Cursor), versioned preview (Lovable, v0), checkpoint with test results (Replit), PR with screenshots and video (Cursor), cited answer (Perplexity).
- **Checkpoints and cheap undo.** Replit checkpoints with Rollback here, Lovable Undo latest edit and Revert and resend, v0 versions with restore, Claude Code Esc keeping work so far.

## The three things none of them do

- **Show what it was supposed to cost and take against what it did.** Replit, Lovable and Computer show cost after; Computer shows an estimate before. None puts predicted beside actual beside promised, per run, as a first-class record. This is the forecast made visible.
- **Show two agents colliding on the same thing.** Every multi-run surface (Codex tasks, Replit board, Claude Code sidebar, Cursor list) is a list of independent rows. None shows overlap between runs or that one is about to undo another's work.
- **Carry the review verdict back into the next run.** Inline comments, ratings and Session Insights (Devin) all improve the next prompt by hand. None records what the person decided at review time, why, and whether it held, so the product can show "last time you sent this back for X" on the next handover.
